# 第8周开源对照反思（300字+改造说明）

1. **我的代码与官方 2-Step RAG 差在哪一步？**
我的 `rag_qa.py` 在逻辑上与官方完全一致，但在工程实现上存在“做法不同”。官方使用了 LangChain 全家桶（TextLoader, Splitter, Chroma 数据库）；而我为了避开 Python 3.15 的兼容性问题，选择了纯原生 `requests` 手写分块和余弦相似度。我虽没用现成的向量库，但完美实现了检索增强的核心逻辑。

2. **B路径加分项改造说明：给 `use_rag` 加“返回出处”开关**
我在 `assistant_v1.py` 中新增了 `return_citation=True/False` 参数。当用户不需要复杂的来源依据时，系统会自动剥离 `[来源：...]` 的字符串，只保留干净的直接答案；当需要学术严谨性时，则保留出处。这提升了产品在不同场景下的交互灵活性。

3. **从 2-Step 走到 Agentic RAG，我需要补什么能力？**
Agentic RAG 允许模型自行决定何时检索。要走到那一步，我需要先补上第9周的**工具调用（Function Calling）**能力，把 `retrieve()` 封装成一个“工具”提供给模型。

4. **llm-universe 没有 LICENSE，为什么只能参考思路不能复制？**
没有 LICENSE 默认“保留所有权利”，复制属于侵权。这与 `.env` 不入仓的红线有共同点：保护知识产权和防止隐私泄露一样，是作为开发者必须具备的数字公民底线。在 README 中诚实写明“已知问题”也是同理，诚实不仅是工程规范，更是专业度的体现。

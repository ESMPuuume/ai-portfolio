# 第四周实录：第一次API调用与踩坑记录

## 一、 任务背景与准备工作
本周任务是编写一个命令行学科问答机器人（`week4_api_bot.py`）。
我使用了 DeepSeek 的 API，并在独立的 `w4` 文件夹中配置了 `.env` 文件存放密钥，同时利用 `.gitignore` 确保密钥不会被推送到 GitHub 仓库，严守了“密钥安全红线”。

## 二、 跌宕起伏的排错实录（最有价值的过程）
在跑通代码的过程中，我遇到了两个典型的底层环境错误，这也是这次作业最大的收获：

1. **DLL load failed (pydantic)**：一开始代码使用了官方的 `openai` 库，但因为我电脑安装的 Python 版本（3.15）过新，导致 `openai` 依赖的 `pydantic` 库出现底层文件不兼容。我尝试了安装微软 C++ 运行库未果后，果断放弃 `openai` SDK，改用更底层的 `requests` 库来直接发送 HTTP 请求，这反而让我更深刻理解了讲义“附录A”中提到的“SDK只是封装”的原理。
2. **charset_normalizer 报错**：改用 `requests` 后，遇到了 `unknown slot ID` 的编码兼容性报错。通过排查，我发现是 Python 3.15 下 `charset-normalizer` 新版本的问题，最终通过在虚拟环境中运行 `pip install charset-normalizer==3.1.0` 降级版本，成功让代码跑通！

## 三、 课堂实验五步记录

### 1. 跑通第一句（附带3个学科问题）
运行了以下三个专业问题（均成功生成回答并追加到了 `chat_log.txt` 中）：
- **Q1**：“对外汉语教学中，把字句的教学难点有哪些”
- **Q2**：“HSK4级对词汇量的要求是多少”
- **Q3**：“给一篇中级汉语作文写三段式评语”

*（注：实测发现，AI 回答 HSK4 词汇量时给出的数字并不完全准确，出现了 1200 词的旧版数据，讲义提示得对，确实需要查证。）*

### 2. 参数体验对比
我手动修改了代码中的参数，感受到了明显的差异：
- **当 temperature=0.0, max_tokens=15 时**：回答极其简短、严谨，直接被硬截断成了半句话（如“把字句是汉语中一种用介词……”），体验到了 token 限制的威力。
- **当 temperature=1.5, max_tokens=60 时**：回答非常发散、富有创造力，甚至用上了比喻等修辞手法。这说明 temperature 参数确实控制着文本生成的随机性/发散度。

### 3. 费用计算
终端显示单次问答消耗：输入约 15 tokens，输出约 800 tokens。
按照 DeepSeek 官网当前价格（假设输入 1元/百万tokens，输出 2元/百万tokens）：
`(15 × 1 + 800 × 2) / 1,000,000 ≈ 0.0016 元`。
完成本周所有实验，花费不到 1 分钱。API 按 Token 计费的方式比包月会员更灵活，非常适合程序化调用。

### 4. 故意制造报错实验
- **缺失密钥**：将 `.env` 文件重命名后运行，终端清晰地弹出了人性化提示：“错误：未设置DEEPSEEK_API_KEY”。这说明代码的异常捕获（try-except）和前置检查起到了作用，不会直接抛出满屏看不懂的红字。
- **网络断开**：关闭 WiFi 后运行代码，终端约等了 20 秒，输出了 `APITimeoutError` 连接超时提示，随后代码安全退出。

## 四、 课后思考题解答

**1. 同一句话问两次，为什么答案不完全一样？如果需要“每次结果一致”，应该改哪个参数？**
- **答**：因为模型本身具有随机性，`temperature` 参数大于 0 时会引入概率采样，导致每次生成不同。如果要结果完全一致，需要将 `temperature` 设为 `0.0`。

**2. AI给出的"HSK4级词汇量是1200个词"这个数字，你能直接写进教案吗？你打算怎么核验？**
- **答**：绝对不能直接写进教案。大模型存在“幻觉”，它可能调取了旧版 HSK 大纲的数据。在 2021 年发布的《国际中文教育中文水平等级标准》中，HSK4 级词汇要求是 1000 词（四级累计 3245 词）。我必须查阅官方发布的标准 PDF 文件进行核实。

**3. 如果要支持多轮追问（记得上一轮说了什么），你觉得需要往 messages 里加什么？**
- **答**：需要将上一轮的问答历史追加到 `messages` 列表中。不仅要有用户的提问（`role: user`），还要有 AI 的回答（`role: assistant`），这样模型才能结合上下文进行“多轮对话”。
